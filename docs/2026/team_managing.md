# 项目管理经验

大二下学期，在实验室牵头下报名参加了大学生创新创业训练和全国大学生操作系统设计大赛。一位SE专业的同学作为项目负责人，我与另一位CS专业的同学作为队员，组成一个队伍共同完成项目。我参加的初衷是想锻炼自己的团队协作能力和表达能力，为之后项目管理积累经验。  

## 项目简介

项目本身是作为[CSCC](https://cscc.educg.net/#/)的一个赛题，内容是对ROS 2机器人操作系统的通信机制DDS进行多维调优，主要是通过根据不同业务场景配置Qos参数来实现的。  

## 项目过程

### 项目前期

项目前期是在校期间完成的，我在当时的重心更多地放在课程学习和应对考试上，并且这是我第一次接触项目，对ROS 2了解并不多，**我认为我没有这个知识基础和编程能力来完成它，大部分工作都要依靠网页版AI对话来进行，于是我的态度比较消极。**由于我觉得依赖AI不能体现我自己的价值和能力，因此我对项目的兴趣和投入都不大。但是我发现队友对该项目比较感兴趣，并且对于项目流程很熟练，包括：

- 前期调研：主要是搜集相关项目前沿论文
- 项目分工：每个队员各司其职，负责自己的板块

在队友的带动和感染之下，我也开始对项目进一步了解和深入。一个队友认为我的软件安装能力较强，于是我在开始主要负责在香橙派上进行ROS 2系统安装、基础工具安装。**我认为我当时的生态位是一个服从安排的士兵，只需要完成负责人分配的任务即可**。但是这一时期我忽略了一个很重要的地方，就是自己的表达问题。

#### 表达问题

我本人是一个十分羞涩的人，在陌生人面前施展不开，而且队友都是十分优秀的同学，我有一种害怕的感觉，因此在项目决策和进度展示的时候，话并不多。这就会造成两个问题：

- ***表达空间受限***：由于形成了不表达的习惯，自己也慢慢交出了选择项目方向的主动权，方向性决定主要就由项目负责人和另一位队友把控。那么一旦出现我自己不愿意看到的局面，我自己就会感到难受与憋屈。
- ***人际交往问题***：自己既然不进行一些表达，那么队友对自己的熟悉程度也不会有所改善，这意味着一种淡漠和别扭。

#### benchmark

之后，由于实验室博士生学长给出先找到benchmark(基准测试)的方向，队友主要负责找到能体现真实场景的工具。最终我们选择使用回放开源工具[RobotPerf](https://github.com/robotperf/benchmarks)已经录制好的真实机器人控制场景的数据集作为负载，编写脚本启动接收节点，采集**延迟、抖动、丢包率**作为未进行调优的DDS基准值。

### 项目中期

在项目中期，初赛提交文档截至日期即将到来，但期末周也随之而来，我们不再每周给学长汇报项目进度，而是为了保研步入了紧张的复习之中。由于专业不同，CS专业考试科目相对较少且考试时间相隔不短，然而SE专业的考试时间极其紧张（包括很多实践作业和期末考试），对于项目负责人来说就有一个明显矛盾：

- ***大创/比赛***：可以申请psip学分，提高综合素质测评分数，有利于评奖评优
- ***考试/保研***：加权成绩和排名是之后保研的硬指标

#### 撂挑子

我们都是成年人，知道什么有利于长远发展。于是我们在开了一个简短的会议之后，一致认为应该先停下来项目的推进，优先准备考试。不出意料，学长对于我们的集体撂挑子行为很失望和生气，**但还是指示我们应该提交一个文档，只要提交就有可能进入决赛，之后假期再推进项目也还有获奖机会，现在如果不提交初赛文档，那么之后没有任何机会。** 

我是支持这个决定的，因为准备一个文档不是很困难的事情，使用AI可以很好的做到这一点。之后队长负责准备文档，我由于可以不用负责项目，感到十分轻松，准备考试的同时还拾起了一年前做过的[一生一芯项目](https://ysyx.oscc.cc/)学习了一定数字逻辑电路的知识。

在停止推进项目之后，我感受到前所未有的轻松感，我意识到这是因为我们所做出的决定所影响的。我对于**集体决策**有了更深的体会——人一定要有自己的立场，为自己的立场辩护，如果心口不一或者把话憋在心里，最终没有选择对自己有利的决定，就会感到难过。反之，如果努力维护自己的正当权益和立场，你就会感到开心。利益，以前在我心里是一个坏坏的词，在此刻甚至成为了一个褒义词。

### 项目后期

说实话，我没有想到能进入决赛。但是进入决赛的后果是暑假不停工，还要继续推进项目。我在到家之后得知还要继续推进项目的消息，心中一时五味杂陈。我曾一度想要放弃，母亲也建议我跟队长申请退出。我知道那样我会很高兴。但是我问了初中好友的建议之后，他认为应该坚持下去。我在一夜反复斟酌话语，两种观点反复转换。最终，我仍然坚持了下来。原因很简单，我之前一直是一个轻易放弃的人，没有责任感，没有归属感。**可是自从步入大学，我意识到自己在家庭中承担的责任，我不能再任性和随意退出，这个项目同理，本质上都是属于我的责任。而我的目标就是成为一个有责任感、能抗住事情的真男人。**这并不意味着我全心全意投入在这上面，我还是保证负责好队长交给我的部分即可，尽力做好。再讲的实在些，自己也没有那么多能量去参与了，应付过去、能够把项目完成就是我的最大指望了。

#### ChatGPT

初中好友是我的一个榜样，他大二就开始实习，成绩不是他所看重的，因此他对于当前行业前沿了解很深入，他推荐我尝试使用Agent进行辅助开发，并告诉我现在的Agent十分智能。我在他的引领下，开始接触Agent。我在B站上搜索了很多相关的视频教程，最终选择了CC-Switch + Codex + Deepseek进行开发。我上手之后发现Agent能够直接在我的项目仓库中进行阅读上下文和编写代码，还能够自行测试。[视频教程链接](https://www.bilibili.com/video/BV1YsNg6eEko/?vd_source=368a94b9efcada3665ab46f16b7ba66c)

于是在Agent的帮助下，我几乎无需过多思考，只需要提我的需求，它就能帮助我完成，只不过有时候会消耗我很多token，仍然记得有一次执行一个任务竟然直接把我在Deepseek里充值的10块钱花光了。总而言之，有了ChatGPT，我对于项目属于三天打鱼两天晒网。加上队友也都有各自的困境，我便没有太过重视了。毕竟情绪才是生活幸福的保障，我不能因为任何挫折和不合自己心意的事情就自暴自弃，应该顺势而为。

在此期间，项目负责人和另一位队友是最忙的，他们都忙于最后的动态Qos自适应机制的代码编写，由于逼近决赛代码提交Deadline，我们并没有沟通自适应机制的思路和细节，也没有做相关工作的调研。此外，队长还负责最终的PPT制作和文档编写。这时候的我在家中刷着视频无精打采，感受不到价值和意义所在。不得不说，项目最后阶段我的态度又陷入自暴自弃，只不过是没有宣告退出而已。

#### Git

值得一提的是，我最后负责项目收尾工作时整理代码仓库的工作，我很喜欢这项工作，学习了很多Git相关的基础知识，学习资料主要是[Git原理揭秘](https://zhuanlan.zhihu.com/p/96631135)、[Learning Git Branch](https://learngitbranching.js.org/?locale=zh_CN)，通过实操和图形化交互，我逐渐理解了Git设计。其中必要重要的几个概念是：

- git add: 将所选文件存入Index缓冲区，Git将会跟踪这些文件，一旦进行切换分支或者拉取操作，被追踪文件内容将会进行切换，然而没有被追踪的文件将不会改变
- git commit: 每一次commit都是一次当前追踪文件的快照，也就是说Git可以很轻松的切换至某一次版本
- git branch: 每个分支实际上都是一个指针指向一个commit的版本

之后，我还准备再深入巩固Git学习成功，正确熟练掌握Git操作，成为一个小专家。

说回项目，由于之前我们都是在香橙派上进行代码编写且没有进行版本控制，因此最开始的commit就变的极其奇怪，很多功能的实现没有分开commit而是聚合在一起提交了上去，所以commit次数也很少。因此这也为之后决赛答辩埋下了隐患。

#### 决赛答辩

最终，我和项目负责人带着最终的项目去往决赛现场。去到学校之后，我们开始了各自对项目的熟悉，我主要是看仓库中的源代码并且下载了VSCode中的Codex插件帮助我理解项目结构。到了决赛答辩当天，主要是队长上台回答评委老师的问题，问题非常犀利和尖锐，主要是：

1. 动态Qos创新，到底相比什么创新了（我的理解是要给出创新之前的动态Qos具体论文是如何做的）？
2. 五状态机之前的策略是什么？肯定不是你们说是五状态就是这五个状态。
3. 其他领域动态Qos的论文有很多，你们是否有借鉴？
4. UDP缓冲区调整导致延迟降低90%，原因是什么？具体解释原理。
5. 代码多少部分是AI创作的？是从头开始写的代码吗？

我们大部分没有回答上来，一切解释都是苍白的，因为AI开发就是我们一直在做的，至少是我一直在做的。**最终我们获得了比赛的参与奖，我心中有点沮丧，但我也强烈认为如果一个项目大部分是通过AI的思路来推进，而缺乏我们作为创作者的思考，那么就算获得了奖项，我也不会高兴和写在简历上。因为简历的本质就是去讲清楚自己做的项目回答了一个什么问题，团队是如何解决问题的，使用AI的思路去创作，相当于放弃人的主观能动性和思考的权力，是实在不应该的。**

#### HR交流

在比赛结束，我与华为2012实验室的操作系统内核开发招聘人员交谈了一会儿。主要问了应该如何准备自己的项目以体现自己的能力，那位学长说要去看对应领域的前沿论文是在研究什么、解决什么样的问题，也就是说要去查阅论文。我深有感触，于是在提问结束后变回宿舍查阅相关的论文和项目，但是还是没有什么头绪。

但是我又通过比赛的招聘手册添加了另一位招聘人员的微信，这次我问的问题都非常具体：

>您好，我是本次操作系统功能实现赛道project1的一名队员，目前是大二升大三。
目前有在大三暑假进行一段实习的规划，比较对操作系统内核开发工程师这个岗位感兴趣。考虑到自己身边没有很多机会去问，您又是目前在业界工作，因此主要想咨询一些求职准备的问题。
首先想咨询的就是内核开发工程师是做下一代操作系统的一个岗位，但是我在网上并没有看到诸如后端开发的成熟的技术栈。因此我还想咨询一下岗位面试时候会考察哪些技术栈、或者硬性指标、能力。
以及昨天咨询了现场的一位华为招聘人员关于面试的信息和要求，他提到面试会考察自己做过的一些项目。于是我准备在大三暑假之前努力搞哪怕一个能看的项目写在简历上。自己目前考虑了以下几个项目方向：
>1. 现阶段自己做过的项目是学校安排的，主要包括：CSAPP配套实验，南京大学模拟器NEMU，xv6操作系统实验，Socket实验。但是这些我认为主要是实验性质，拿不出手。本次比赛的项目也和内核沾不上边，同样拿不出手。所以我昨天就去搜了相关的信息。其中包括uCore、rCore这种清华大学教学性的内核，然后我了解到本次内核大赛其实也有队伍是在这两个内核上进行完善。于是我打算接触一下这些小型项目。您认为这些项目怎么样？
>2. 以及自己做了一段时间的“一生一芯”项目，主要是讲处理器设计的项目，最终能够有自己的芯片，但是做了一部分后觉得还是偏硬件一点，因为会写一些Verilog代码描述电路，与我的规划有一定的冲突。我是不是应该放弃这种偏硬件的项目集中精力在软件内核上做呢？
>3. 还有就是关于科研实验室的，有的同学是通过做实验室的项目，拿来写在简历上，甚至有一定的论文产出。我也准备根据情况选择OS相关实验室加入从而积累项目经验。
>以上就是我目前的关于项目的一些选择和取舍，不知道您对于项目选择有什么建议吗，或者说建议我怎么做、做些什么项目呢？因为我也清楚实习本身也是学习和提高自己的一个机会，并且所做的东西是跟企业的业务相挂钩的，所以我想了解您的视角应该准备项目会比较好。
由于自己认知还是局限在学校，因此非常感谢这次机会能与相关岗位负责人沟通和询问。

这位前辈的回答也很具体：

>1. 这些小型的项目不错。这些操作系统内核的项目，我了解有一些会给你一个模板代码，然后让你基于这个模板上做一些改进，比如内核性能/文件系统之类的，这种项目就很适合。
>2. 确实和内核的关系远了，建议放弃芯片的设计方向。不过有一个内容是“在芯片硬件的基础上，调试操作系统内核启动”，算是软硬之间的部分，这个如果有机会涉及的话可以接触一下。

第3个问题学长没有给出具体回答，而是表示如果我有考虑读研的话可以帮忙引荐了一下我进入他研究生时所工作的软件所。总的来说，这次比赛还是收获了太多经验，并且增添了几分处理事情的勇气。

## 项目经验

### 1. 充分的表达空间

在团队中每个人都要有自己的表达空间。在项目初期，由于性格问题，我有很多想法不敢表达而导致之后主动“交枪”，放弃了表达权。但这会导致我越来越被动，成为一个执行命令的队员，我一再强调，这等于丧失了决定团队方向的权利。

### 2. 合理的沟通
